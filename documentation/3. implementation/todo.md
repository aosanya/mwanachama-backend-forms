| F3 | 🐞 **BUG — `Publish` mutates a Form's status to `open` before attempting to create its `PublicLink` row, so a colliding `candidate_link_key` both 500s the request AND permanently strands the Form `open` with no link ever created.** `form_impl.go`'s `Publish` (`form_impl.go:198`) issues the `Forms` status/`published_at` `Updates()` (`form_impl.go:232`) and the `PublicLinks` `Create()` (`form_impl.go:242`) as two separate, non-transactional statements. `PublicLinkRow.Key` is uniquely indexed (`gormstore/public.go:14`), so when a second form is published with a `candidate_link_key` that collides with any other form's already-active link key, the `Create()` fails on the unique constraint — but the Form's own status update already committed first. `errors.go` has no sentinel for this (same missing-`ErrDuplicateID`-class gap as F1), so `formStatusFor`'s default case answers an opaque `500`. The real damage is what happens next: `Publish`'s own first branch (`case models.StatusOpen: return f, models.PublicLink{}, nil`) means *every* future call to `Publish` on that form — with the same key, a fresh key, anything — now silently no-ops, returning `200`/no error and an **empty** `PublicLink`, never attempting the insert again. A public-audience Form is left permanently `open`, unreachable by any public key, published-looking on every read, with no route or manager method able to recover it. Demonstrated through the real `routes.Routes(fm, names)` mux and direct manager calls (`routes/f3_publish_key_collision_test.go`, `TestPublishForm_PinsColldingLinkKeyStrandsFormOpenWithNoLink`): Form A publishes with key `"shared-key"` (succeeds); `POST /forms/{formB}/publish {"candidate_link_key":"shared-key",...}` returns `500`; a direct `fm.Get` immediately after shows Form B's `Status` is already `"open"`; a retry `fm.Publish(formB, "a-perfectly-fine-fresh-key", ...)` returns `nil` error and a zero-value `PublicLink{}` — no link, ever. **Fix location**: `form_impl.go`'s `Publish` — wrap the Form-status update and the PublicLink insert in one transaction (so a failed link insert rolls the status change back too, matching `errors.go`'s existing "let the database catch the race" philosophy this repo's CLAUDE.md notes elsewhere), and/or add a duplicate-link-key sentinel mapped to a clean `409` in `formStatusFor` instead of the opaque `500`. | 📋 | Found by the fleet integration-test sweep (loophole catalogue #10: rejection paths' state-after), while confirming the F1-carried lead about `AddOption`/`VersionQuestion` did NOT apply — both take no id-bearing struct from the wire (`routes/question.go`'s `AddOption`/`VersionQuestion` handlers decode only `label`/a full field-by-field `questionBody` with no `id` field, and `question_impl.go`'s `AddOption`/`VersionQuestion` both construct their new row's `models.Question`/`models.QuestionOption` explicitly field-by-field, never copying any wire-supplied `ID`) — ruled out, not a live vector, before moving on to probe `Publish`'s own second write (the `PublicLink` insert) for the same non-transactional-partial-write shape F1 already found on `CreateForm`. Also probed and ruled out in the same pass: `ValidateAnswer`'s collapsed `ErrInvalidAnswer` still correctly rejects all three original reasons (shape/length/unknown-option — confirmed by reading `models/answer.go` against the existing `public_test.go` coverage, no gap found); `PropagationKind`'s `Localized`/`Pushed` dead vocabulary is confirmed genuinely unreachable (`routes/propagation.go` exposes only `ListPropagation`/`Rollup`/`PickUp`, none of which ever set those two states); `Respondent`'s lack of any `FormID`/link binding (so a `public_key` minted via one form's link legitimately resolves against a different form's link too) is confirmed intentional, documented upstream-mirroring behavior (`models/public.go`'s own doc comment), not a fresh defect. Pinning test committed in `routes/f3_publish_key_collision_test.go` — asserts the *current* broken behavior end to end (500 on the colliding publish, `Status == "open"` immediately after, then a silent no-op retry that never mints a link) and documents in its own comment what must flip once fixed. `go test ./...` and `go test -tags=integration ./...` both green with this test added. |
