# FMD-001 — The objects are declared, not written: forms adopts the declared-domain format

Decided with the owner on 2026-09-28, against
`mwanachama-backend-catalog` as the reference shape and
`mwanachama-backend-agency`'s AGD-007 as the worked precedent. Implemented
as F6–F12 on [../3. implementation/todo.md](../3.%20implementation/todo.md).

The format itself is documented once, in
[declared-domains.md](../../../mwanachama-backend-shared/documentation/2.%20design/declared-domains.md)
and [dispatcher.md](../../../mwanachama-backend-shared/documentation/2.%20design/dispatcher.md).
This page records only what was decided *for this repo*, and what turned out
to be true that the plan assumed otherwise.

## The four questions F6 asked, and their answers

**Is the conversion complete, or the data layer only?** Complete: storage
and HTTP both. There is no MCP surface here to convert, so it stops there.

**What do the declared tables get called?** `<instance>_forms_<object>`,
like every other converted module. The instance is a mount's choice, through
`SpecFor(instance)`; the shipped `forms.forms.json` names `wakala` as an
example rather than as a fixed answer. `Provision` renames a pre-spec table
set (`<instance>_<object>`) onto the declared names before creating what is
missing, so a database that predates this keeps its rows.

**Is F5's form→record mapping declared in the blueprint?** No. F5 is still
an open design — its own row leaves unanswered whether the target is always
`catalog` or any module — and declaring a mapping now would be guessing at
its shape. Converting first still pays for itself: once F5 is designed, it
is a blueprint edit plus the Go that a spec cannot state, rather than a new
table and a new row struct.

**What happens to the trigger, the CHECK and the partial unique index?**
They move into `Provision` as raw SQL, Postgres only, exactly as
`gormstore/tables.go`'s `syncConstraints` applied them. None of the three is
expressible in the format: two have no declared equivalent at all, and the
third is a partial index over `decided_at = ''` rather than over `deleted`,
which is the only condition the format names. The Go rules that enforce the
same three are what the SQLite unit tests exercise.

## Three things the plan assumed that were not true

**The live tables were never called `survey*`.** F8 was written believing
the gateway's Postgres schema still used the pre-extraction `survey_*`
names and that the conversion had a rename to negotiate. It does not:
`cmd/server/stores.go` has called `DefaultTableNames("form")` since the
2026-09-05 cutover, and migration `000003_form_tables.up.sql` was rewritten
at the time to match. The rename this conversion performs is the ordinary
one every converted module performs — inserting the module segment.

**This repo's `routes/` package had no consumer.** F10 and F11 were written
as though converting the route table were a change to a live surface. It was
not: `mwanachama-backend-api-gateway` drives `FormManager` through its own
`internal/store/formsadapter` and serves its own `survey_*_handlers.go`
addresses, and nothing outside this repo ever imported
`mwanachama-backend-forms/routes`. That is what made it safe to change the
request shapes the conversion had to change.

**The consumer that matters is `mwanachama-wakala-api`, not the gateway.**
Owner's direction mid-conversion. F11 as written named the gateway's Postman
gate as the acceptance; what shipped instead is a real mount in wakala-api,
built the way its catalog mount is, with the gateway held to still building
and testing green. The gateway's Postman gate is red for
`/v1/agency/*` coverage (DEV-1693/DEV-1694) and this conversion moved
neither number.

## What the conversion changed that a caller can see

Nothing outside this repo consumed these addresses, so none of this was a
break. Recorded because the shapes are now the declared ones and will not
move again without an edit to `forms.operations.json`.

- **Path wildcards are snake_case** — `{form_id}`, not `{formID}`. The URLs
  a caller sends are unchanged; the mux patterns are not.
- **The narrow request structs are gone.** `AddTarget` and `UpdateForm` took
  hand-written bodies carrying a handful of fields; they now take the domain
  type whole. That is safe because both server-owned fields they would newly
  expose — a target's `id` and `created_at` — are overwritten unconditionally
  by the manager, which is where F4 was actually closed.
- **The address outranks the body.** `POST /forms/{form_id}/targets` and
  `POST /forms/{form_id}/questions` take their form from the address and
  overwrite whatever the body claimed, declared as `into`. Both are pinned.
- **`actor_id` comes from the mount, not the request.** `AddOption` and
  `VersionQuestion` read it through `from: caller`, so no request and no MCP
  tool can name who did something. Neither method used the value, which is
  why this cost nothing.
- **Every address carries an action**, and only three are anonymous:
  opening a shareable link, registering a respondent behind one, and
  declaring a chapter behind one. Answering is deliberately not among them
  — this module cannot tell a public respondent from a member, so an
  ungated write would let anyone answer any open form as anyone.

## Two signature changes the format forced

Both are consequences of how the dispatcher binds, not preferences.

**`AddQuestion`/`UpdateQuestion`/`VersionQuestion` take one
`models.QuestionDraft`** — a `Question` with its `Options` — instead of a
`Question` and a slice. A request has at most one *whole* body, and only a
whole body can be overwritten by the address. Two parameters would have
meant taking the form id from the body, which is exactly the write that
lands on a form the caller was not addressing.

**The public-link surface is three new manager methods** —
`OpenPublicLink`, `RegisterRespondent`, `DeclareChapter`. The three handlers
this replaces each resolved the key, refused with a bare 404, and only then
called the manager; `DeclareChapter`'s also took the form id from the key
rather than from the caller. None of that is argument binding, and the
dispatcher is right not to express it: every rule about who may see what
belongs in the manager. `ErrLinkNotFound` carries the text `not found` and
nothing else, so the refusal still names none of the several ways to fail.

## What the engine needed before any of this could work

`mwanachama-backend-shared`'s `spec` and `specstore` could carry only
`string`, `bool` and `int`. Five of this module's fields are none of those:
`Question.MaxLength` (`*int`), `Question.QuickPicks` (`[]float64`),
`Answer.OptionIDs` (`[]string`), `Answer.ValueNumber` (`*float64`) and
`Answer.ValueBool` (`*bool`). Catalog and agency are all-scalar, which is
why neither met this.

The owner chose extending the engine over flattening these types or hiding
them behind private carrier structs. `spec` gained a `float` type and a
per-field `nullable` flag; `specstore` gained pointer, float and
JSON-collection arms on both sides of the codec, and now **refuses at
construction a carrier that cannot hold the distinction** — a nullable
column carried by a plain value, or a pointer landing in a column nobody
declared nullable. `mwanachama-backend-comm`'s own conversion is the second
consumer of that work.

One bug surfaced with it: `ColumnName` derived `option_i_ds` from
`OptionIDs`, because a trailing plural after an initialism read as the start
of a new word. A lone trailing `s` now pluralises the run it follows. No
converted module had a field of that shape, so nothing was storing to a
wrong column — but this one would have been.

**The construction-time refusal earned itself in another repo within the
hour.** `mwanachama-backend-comm`'s own conversion declared eleven nullable
fields and got seventeen of them wrong on the first pass, by reading
nullability off the old GORM row structs: `Report.Note` and
`Removal.RemovedBy` are `*string` in the row struct but plain `string` on
the domain type, because the deleted `ToRow` pairs did the converting. That
is the exact shape the check exists for — every one of those would otherwise
have been a column that reads back empty forever, with nothing reporting it.
Worth knowing for whichever module converts next, and especially for
`accounting`, which comes from entitygraph rather than from row structs and
so has no old struct to read nullability off at all.
